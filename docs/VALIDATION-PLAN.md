# Padnote 跨平台完整驗證計劃

> 目標：用一套可重複執行、可追蹤、可擴充的驗證流程，確認 Padnote 從第一層主架構到各功能項下的子功能，在 Apple、Android、不同螢幕尺寸、不同輸入方式與資料狀態下，都正常可用且符合產品設計邏輯。
>
> 相關文件：
> - `docs/features.md`：功能範圍與產品目標
> - `docs/PLATFORM-PARITY.md`：Apple / Android 功能對等清查
> - `docs/TEST-CHECKLIST.md`：需要真機驗證的實測清單
> - `docs/DEVLOG.md`：每版修改與驗證紀錄

---

## 1. 驗證原則

Padnote 的驗證不能只看「畫面能不能打開」或「按鈕能不能按」。每一項功能都要同時通過以下五層：

| 層級 | 要回答的問題 | 失敗範例 |
|---|---|---|
| 功能正確性 | 操作結果是否正確？ | 建立筆記後列表沒有出現 |
| 設計邏輯 | 使用流程是否符合產品意圖？ | 同步失敗卻看起來像成功 |
| 資料安全 | 是否可能遺失、覆蓋或破壞資料？ | 兩台裝置同步後其中一邊筆畫消失 |
| 跨平台一致性 | Apple / Android 是否有相同能力或明確平台差異？ | Android 有功能但 Apple 無入口，文件也未說明 |
| 跨尺寸可用性 | 小螢幕、平板、桌面、分割視窗是否可操作？ | 工具列被擠出畫面，彈窗無法關閉 |

發佈前不得以「大致可用」作為驗收語言。每個測試項目都必須有可當場判定的結果。

## 3. 測試案例模板

每一個主功能與子功能都用同一個模板描述。

```text
功能名稱：
所屬節點：
平台：
設備 / 螢幕：
前置條件：
操作步驟：
預期結果：
設計邏輯：
資料狀態：
邊界情境：
錯誤情境：
跨平台要求：
自動化層級：
真機需求：
驗收優先級：
```

範例：

```text
功能名稱：兩台裝置同步同一頁筆畫
所屬節點：同步 / 備份 / 安全 > 衝突合併
平台：Apple + Android
設備 / 螢幕：iPad + Android tablet
前置條件：兩台裝置指向同一個同步資料夾
操作步驟：
1. A 裝置在第一頁寫三筆
2. B 裝置在同一頁寫三筆
3. A 執行同步
4. B 執行同步
5. A 再次同步

預期結果：
1. 兩台裝置都看到六筆
2. 頁數不增加
3. 筆畫不變粗、不重複
4. 沒有任何一邊被覆蓋

設計邏輯：
Append-only / CRDT 合併應保證兩邊修改都保留。

資料狀態：
同步前、同步後、重開 App 後都要一致。

邊界情境：
弱網路、同步中斷、同時改標題。

錯誤情境：
同步資料夾權限失效時要明確提示。

跨平台要求：
Apple / Android 行為一致；平台檔案選擇器可以不同。

自動化層級：
核心合併邏輯用 unit / integration；真機同步用 manual。

真機需求：
是，至少兩台設備。

驗收優先級：
P0。
```

## 4. 平台與設備矩陣

### 4.1 平台

| 平台 | 最低覆蓋 | 重點 |
|---|---|---|
| iOS | iPhone + iPad | 觸控、鍵盤彈出、權限、分享面板 |
| iPadOS | iPad + Apple Pencil | 手寫、掌拒、分割畫面、多視窗 |
| macOS | Intel / Apple Silicon 擇主要發佈目標 | 視窗、沙盒、檔案權限、鍵盤滑鼠 |
| Android | Phone + Tablet | Stylus、Google Drive、檔案選擇器、Play services |

### 4.2 螢幕尺寸

| 類型 | 建議尺寸 | 必測項目 |
|---|---|---|
| 小型手機 | 320px / 360px 寬 | 工具列收合、彈窗高度、鍵盤遮擋 |
| 常見手機 | 375px / 390px / 414px 寬 | 首頁、編輯器、設定、分享流程 |
| 手機橫向 | 568px 到 932px 寬 | 工具列、頁面縮放、彈窗 |
| 小平板 | 768px / 834px 寬 | 側欄、頁面縮圖、分割視窗 |
| 大平板 | 1024px / 1194px 寬 | Apple Pencil、雙欄或多面板佈局 |
| 桌面小窗 | 800x600 / 1024x768 | 最小可用視窗 |
| 桌面標準 | 1280x720 / 1440x900 / 1920x1080 | 常態工作流程 |
| 高 DPI | Retina / Windows 125% / 150% 等效 | 圖示、文字、PDF 預覽、筆畫 |

### 4.3 輸入方式

| 輸入方式 | 驗證重點 |
|---|---|
| 手指觸控 | 捲動、選取、長按、拖曳、縮放 |
| Apple Pencil / Stylus | 筆跡、壓感、傾斜、掌拒、延遲 |
| 滑鼠 | 右鍵選單、拖曳、滾輪、精準選取 |
| 鍵盤 | 文字輸入、快捷鍵、Tab 順序、Esc 關閉 |
| 系統分享 / 檔案選擇器 | 匯入、匯出、同步資料夾、備份還原 |

## 5. 設計邏輯驗證

每個畫面與流程都要通過以下設計邏輯檢查：

| 類別 | 檢查問題 |
|---|---|
| 導航 | 使用者是否能從子功能回到合理位置？返回行為是否符合平台慣例？ |
| 狀態 | 空狀態、載入中、成功、失敗、離線、無權限是否都有可理解呈現？ |
| 主次 | 主操作是否明顯？危險操作是否需要確認？常用操作是否不被藏太深？ |
| 資料 | 何時保存？保存失敗如何提示？離開畫面是否有資料遺失風險？ |
| 響應式 | 小螢幕是重排、收合還是改成 sheet？被收合的功能是否仍可到達？ |
| 平台慣例 | Apple / Android 可以有不同外觀，但同一個任務不應有不同結果。 |
| 錯誤恢復 | 失敗後使用者是否知道發生什麼事、能否重試、資料是否保留？ |

禁止只驗證 happy path。所有 P0 / P1 功能至少要有一個失敗路徑測試。

## 6. 跨尺寸 UI 檢查

每個主要頁面在每個斷點都要檢查：

| 項目 | 判準 |
|---|---|
| 文字 | 不得被截斷到不可理解；多語系長字串不能溢出 |
| 工具列 | 不得超出畫面；收合後所有功能仍可到達 |
| 按鈕 | 觸控目標足夠；不能互相重疊 |
| 彈窗 / Sheet | 小螢幕可滾動、可關閉、底部操作不被系統列遮住 |
| 鍵盤 | 輸入框不被鍵盤遮住；送出 / 取消仍可操作 |
| 畫布 | 頁面邊界、可列印區、縮放與捲動符合預期 |
| 側欄 | 收合 / 展開不會造成內容狀態遺失 |
| 圖示 | 高 DPI 下清楚，不模糊 |
| 旋轉 | 直向 / 橫向切換後狀態不錯亂 |
| 系統字體 | iOS 動態字級、Android 字體大小、桌面縮放仍可操作 |

## 7. 核心 E2E 流程

以下流程是每次大版本發佈前必跑的最小集合。

| 流程 | 步驟摘要 | 優先 |
|---|---|---|
| 首次使用 | 安裝 → 啟動 → 權限 → 建立第一則筆記 → 重開確認 | P0 |
| 日常手寫 | 開啟筆記 → 手寫 → 擦除 → 復原 → 自動保存 → 重開確認 | P0 |
| 混合內容 | 手寫 + 文字 + 圖片 + 表格 + 形狀 → 移動/縮放 → 保存 | P0 |
| 匯出 PDF | 建立含多種物件筆記 → 匯出 PDF → 第三方 App 開啟檢查 | P0 |
| 備份復原 | 建立備份 → 清除資料 / 重裝 → 復原 → 所有內容回來 | P0 |
| 跨設備同步 | A 建立 → 同步 → B 顯示 → B 修改 → A 收到更新 | P0 |
| 同步衝突 | 兩台同頁修改 → 各自同步 → 雙方內容都保留 | P0 |
| 離線恢復 | 離線建立 / 修改 → 恢復網路 → 同步成功 | P1 |
| 錄音轉錄 | 授權麥克風 → 錄音 → 停止 → 轉錄 / 回放 | P1 |
| 搜尋 | 打字、手寫辨識、轉錄、PDF / OCR 內容進索引後可查 | P1 |
| 語言切換 | 切換六語系 → 主要畫面、錯誤訊息、文件正常 | P1 |
| 權限拒絕 | 拒絕麥克風 / 檔案 / Drive 權限 → 明確提示且可恢復 | P1 |

## 8. 自動化測試分層

| 層級 | 目的 | 適合覆蓋 |
|---|---|---|
| Unit | 驗證純邏輯 | CRDT 合併、格式解析、搜尋規則、加密、座標轉換 |
| Integration | 驗證模組互動 | 編輯器保存、匯出管線、同步 I/O、模型下載狀態 |
| UI / E2E | 驗證主要流程 | 建立筆記、編輯、匯出、備份、設定 |
| Visual Regression | 驗證跨尺寸 UI | 首頁、編輯器、設定、彈窗、錯誤狀態 |
| Performance | 驗證預算 | 啟動、PDF 開啟、筆跡延遲、記憶體、搜尋 |

優先自動化順序：

1. 會造成資料遺失的流程。
2. 每次 release 都一定會跑的主流程。
3. 曾經出錯過的功能。
4. 跨平台共用核心邏輯。
5. 多語系與響應式容易回歸的 UI。

真機手測不可被自動化完全取代，尤其是手寫手感、掌拒、鍵盤遮擋、系統分享面板、雲端 provider 與分割視窗。

## 9. 發佈門檻

| 等級 | 定義 | 發佈要求 |
|---|---|---|
| P0 | 資料遺失、無法啟動、主要流程不可用、同步覆蓋資料 | 必須全部修復 |
| P1 | 主要功能失效、嚴重 UI 遮擋、無法恢復的錯誤狀態 | 必須全部修復或明確降級停用 |
| P2 | 次要功能瑕疵、局部體驗問題 | 可帶著已記錄 issue 發佈 |
| P3 | 純視覺微調、文案瑕疵 | 可排入後續 |

每次發佈前至少要滿足：

1. 核心 E2E 流程全部通過。
2. Apple / Android 對等清查沒有未說明的新落差。
3. 真機測試清單中本版觸及項目全部通過。
4. 沒有 P0 / P1 開放問題。
5. 舊資料升級測試通過。
6. 匯出、備份、復原、同步都至少跑過一次。
7. 多語系與最小螢幕尺寸沒有不可操作畫面。

## 10. 文件維護規則

為了避免文件過期造成誤導，新增或修改功能時必須同步更新以下內容：

| 修改類型 | 必須更新 |
|---|---|
| 新功能 | `docs/features.md`、本文件功能樹、必要時 `docs/TEST-CHECKLIST.md` |
| 跨平台差異 | `docs/PLATFORM-PARITY.md` |
| 需要真機確認 | `docs/TEST-CHECKLIST.md` |
| 版本修復 / 已驗證事項 | `docs/DEVLOG.md` |
| 格式或資料相容性 | `docs/format-spec.md` 或對應架構文件 |

任何清單如果發現已過期，修正清單本身也是該次工作的必要交付，不應留給下一次。

## 11. 建議執行節奏

| 時機 | 執行內容 |
|---|---|
| 開發中 | Unit / integration，針對變更區域補測 |
| 合併前 | 相關主流程 E2E、平台對等檢查、必要截圖 |
| 每日或每個 milestone | 核心 E2E、資料安全、匯出、同步 |
| 發佈前 | 完整設備矩陣、真機測試清單、舊資料升級 |
| 發佈後 | Crash、同步錯誤、備份 / 復原回報、使用者實機回饋 |

Padnote 的驗證重點是「資料不可丟、功能要對等、不同設備都可工作」。自動化負責穩定重複的部分，真機驗證負責物理輸入、平台權限與實際雲端行為；兩者缺一不可。
