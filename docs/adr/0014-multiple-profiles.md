# ADR-0014：一台裝置多位使用者（設定檔）

> 狀態：**已採納**（2026-10-13）
> 相關：`scripts/check-profile-scope.py`、`apple/Sources/ProfileManager.swift`、`android/.../profile/`

## 背景

教室與家庭會共用一台 iPad／平板。系統層的多使用者只有 macOS 與（部分）Android 平板有；
iPadOS／iPhone 沒有（只有教育機構受管裝置的「共用 iPad」）。需求是像電腦的多個登入帳號：
一台裝置最多 5 位使用者，各自的筆記、偏好、雲端帳號與同步完全分開，切換迅速，
切來切去之後每個人的環境都原樣。

## 決策

**App 內「設定檔（profile）」，切換時整個使用者環境換掉。**

- **預設設定檔 = 升級前就存在的那一份資料**，位置、偏好鍵名、Keychain 項目名**全部不變**。
  既有使用者升級後沒有任何東西被搬動或改名；只有新增的設定檔才用新位置。
- **每個設定檔是同步協定裡獨立的一台裝置**（自己的 `deviceId`、自己的雲端快照）。
  不需要改核心。
- **一個 Google 帳號只能綁一個設定檔。** 範例筆記的 id 是固定的，兩個設定檔登入同一個帳號，
  雲端上的筆記就混在一起。
- **PIN 是基礎，生物辨識只是它上面的捷徑；忘記 PIN 沒有救援。** 用裝置密碼救援的話，
  知道裝置密碼的家人就能重設別人的 PIN —— 那正是這個鎖要擋的對象。
- **預設設定檔不能刪**（它對應升級前的資料，位置可能是使用者自己選的）。
- 上限 5 個。沒有訪客。

### 切換：Apple 就地重設，Android 重啟行程

- **Apple**：iOS 不允許 App 自己重啟，所以 25 個單例逐一實作 `prepare / finish / resetForProfileSwitch`。
  順序是硬性的（見 `ProfileManager.swift` 檔頭）：先拆畫面（編輯器在舊設定檔還有效時存檔）、
  再停活動、取得全域同步閘門、最後存檔，然後才切、才重載。
  **最危險的不是讀到別人的資料，而是舊設定檔的寫入落到新設定檔的目錄** —— 範例筆記的 id 在每個
  設定檔都一樣，這種錯不會報任何錯誤。
- **Android**：重啟行程。記憶體裡（92 個單例、Compose 的 `remember`、各種快取）沒有任何東西
  會留給下一個使用者 —— 不必證明「每一個都重設了」，因為它們根本不存在了。
  代價是多一次冷啟動（約一兩秒）。重啟用獨立行程（`:restart`）的跳板 Activity 完成。

### 把紀律變成機器檢查

`scripts/check-profile-scope.py`（pre-push 門禁）：每個單例、每個全域可變狀態、每個直接取用
`UserDefaults`／`SharedPreferences`／`filesDir` 的地方，都必須分類成「裝置共用」或「屬於設定檔」；
Apple 標成「屬於設定檔」的單例必須實作 `resetForProfileSwitch`。新增一個沒分類的狀態，提交就被擋下。

## 沒有解決的（老實說）

- **這是邏輯隔離，不是加密隔離。** 資料在 App 沙盒裡，核心直接讀寫檔案，沒有針對設定檔的加密層。
  PIN 擋的是「不小心點進來」。真正的保密要靠 macOS／Android 的系統使用者或裝置密碼。
- **Mac**：新設定檔的資料放在 App 容器內，不在 Finder 看得到的文件資料夾（預設設定檔仍由使用者選位置，
  符合 Mac App Store 對使用者文件的要求）。要取出用「資料備份」。Mac 本來就有系統使用者，輪流使用
  同一台 Mac 的人用那個更合適。
- **背景同步只服務「最後使用中」的設定檔**（iOS 的 BGTask、Android 的 WorkManager）。其他設定檔在被
  切進來時，由進前景的立即同步補上。切換前會先把還沒上傳的最後一筆編輯推出去（最多等 3 秒）。
- 同一個設定檔內進行中的語音轉錄（呼叫端畫面的 `Task`）在切換時取消不到；它的結果依「錄音所在筆記本
  的唯一 id」寫回，切換之後在另一個設定檔裡找不到，所以不會寫進別人的筆記。
- Android 自動備份**不備份** PIN 紀錄（Keystore 金鑰不會跟著還原，備份了也讀不出來）：換機後鎖要重設。
