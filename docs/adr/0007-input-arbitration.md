# ADR-0007：輸入仲裁與掌拒

- 狀態：**已接受**（2026-09-12）
- 決策：D-08（壓感語意）
- 相關：`docs/input-design.md`、S-36

## 背景
手寫 App 若沒有掌拒，使用者把手掌靠在螢幕上寫字會畫出大片塗鴉 ——
這是產品的生死線，不是體驗優化。

同時需要決定壓感的語意：按壓深度要觸發什麼？

## 決策

### 1. 仲裁邏輯放在 Rust core，不放平台層
平台層只負責把原始指標事件轉成統一的 `PointerEvent` 餵進來；
**分類（筆／指／滑鼠／手掌）與是否採納由 core 決定**。

理由：掌拒的判準會隨真實使用不斷調整。若邏輯散在 Swift 與 Kotlin，
兩邊必然長歪，而且無法寫測試 —— 這種靠經驗值調出來的邏輯**最需要迴歸測試**。

### 2. 掌拒採「多重訊號 + 平台優先」
| 訊號 | 用途 |
|---|---|
| 平台分類（`UITouch.type == .pencil`） | **最強**，有就直接採信 |
| 接觸面積（`majorRadius`） | 手掌接觸面積遠大於筆尖 |
| 筆優先（pen-down 後鎖定） | 筆落下後，同時存在的觸控一律視為手掌 |
| 模式（僅筆書寫） | 使用者可強制忽略手指輸入 |

### 3. 壓感語意可設定，預設為線寬與濃度（D-08）
使用者可從以下選項設定：

| 選項 | 說明 |
|---|---|
| `StrokeWidth`（預設） | 壓感調變線寬 |
| `Opacity` | 壓感調變濃度 |
| `WidthAndOpacity` | 兩者同時 |
| `QuickToolbar` | 重壓叫出快顯工具列 |
| `None` | 不使用壓感 |

**為什麼預設是線寬**：那是使用者對「筆」的既有預期。
把重壓綁定到叫工具列會讓用力寫字的人不斷誤觸。

## 後果
- 平台層變薄：只做事件轉換，不做判斷
- 掌拒的每一條判準都有測試，調整時不會回歸
- 壓感語意進設定，需要 UI 支援（併入 S-37）
