# ADR-0002：筆畫不進 CRDT

- 狀態：**已接受**（2026-09-12）
- 相關：`format-spec.md` §5、§6

## 背景
文件需要 CRDT 才能在無伺服器下收斂。但一筆畫含數百個取樣點，若每個點都是
CRDT 元素，op 數量會爆炸，合併成本與儲存開銷都不可接受。

## 決策
- 筆畫走獨立的 **append-only 二進位串流**（`ink/<page>.strokes`）
- 擦除不刪除位元組，而是追加 `Remove` 墓碑
- CRDT 只持有 `page_uuid → strokes 檔` 的引用

## 理由
新增與刪除墓碑天生可交換且冪等 —— 這正是收斂所需的全部性質，不需要完整 CRDT
的機制。`materialize()` 的測試明確驗證「墓碑先於新增」也能正確收斂。

## 後果
- 筆畫檔會單調成長，需要墓碑 GC 策略（`format-spec.md` §9 待決）
- 換取的是：寫入路徑極短（落筆到落盤 <1ms），這是 J1 延遲預算的前提
