# ADR-0009：可編輯的嵌入文件

- 狀態：**已接受**（2026-09-12）
- 決策：D-10
- 相關：`docs/requirements-review.md` §7

## 背景
需求：試算表與簡報放進手寫筆記本要能**嵌入且可編輯**。

## 決策
引入 **`EmbeddedDocument` 區塊**，分三種互動層級：

| 層級 | 行為 | 適用 |
|---|---|---|
| `Preview` | 渲染為圖像，可縮放、可標註，**不可改內容** | 簡報、複雜排版的文件 |
| `Editable` | 在筆記內直接編輯 | 試算表的儲存格、純文字文件 |
| `Linked` | 只存連結與快照，開啟時跳到原生 App | 大型或高保真需求的檔案 |

**預設依格式決定**：
- `.md` / `.txt` / `.json` → `Editable`（本來就是文字）
- `.xlsx` / Google 試算表 → `Editable`（值與公式結果，**不支援巨集與樞紐**）
- `.docx` / Google 文件 → `Editable`（段落與基本樣式，**不保證複雜排版**）
- `.pptx` / Google 簡報 → `Preview`（版面保真優先；編輯請回原生 App）

## ⚠️ 明確的範圍限制
**可編輯不等於完整相容。** 我們不是要做 Office 的替代品：

- 試算表：支援值、基本公式、格式；**不支援**巨集、樞紐分析、圖表編輯
- 文件：支援段落、標題、清單、粗斜體；**不保證**分欄、浮動圖文、追蹤修訂
- 簡報：唯讀預覽；編輯需回原生 App

**往返保真（round-trip fidelity）不保證。** 匯入後編輯再匯出，
複雜排版會流失。UI 必須明示這一點，不能讓使用者以為可以拿 Padnote
當 Office 用。

## 後果
- `.padnote` 格式新增 `EmbeddedDocument` 區塊類型（與 S-38 的物件模型一併設計）
- 需要 OOXML 解析：`docx-rs`（文件）、`calamine`（試算表）；
  `pptx` 生態缺成熟解析器，因此簡報只做預覽
- Google 三件套需 OAuth + Drive export 端點 → 與 D3 相同的外部依賴考量，
  排在本機檔案之後
