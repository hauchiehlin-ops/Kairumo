# ADR-0010：物件模型（群組、變換、對齊）

- 狀態：**已接受**（2026-09-12）
- 工作項：S-38
- 相關：ADR-0002（筆畫不進 CRDT）、`format-spec.md`

## 背景
需求要「物件可以群組、自動與手動對齊」。但目前 `Stroke` 只有 id 與
頁面座標，**沒有「物件」的概念** —— 無法群組，也無法整體移動或縮放。

## 核心約束：不能破壞「存原始取樣點」

ADR-0002 定下：筆畫存原始取樣點，不做破壞性處理。
理由是未來換渲染演算法或訓練 HWR 模型時，歷史筆記能回溯受益。

如果縮放物件時直接改寫取樣點座標，這個性質就沒了 ——
而且反覆縮放會累積浮點誤差，筆跡逐漸走樣。

## 決策

### 1. 物件持有仿射變換，取樣點永不改寫
```text
ObjectNode { id, kind, transform: Affine2 }
```
渲染與命中測試時把變換**套用在讀取端**，儲存的座標始終是原始值。

反覆縮放只會改變矩陣，不會累積取樣點的誤差。

### 2. 物件樹，變換沿路徑相乘
群組可以巢狀。某個筆畫的最終變換 = 從根到它的所有 `transform` 相乘。

### 3. 群組是「引用」不是「搬移」
群組只記錄成員 id，筆畫仍留在原本的 `ink/<page>.strokes` 串流裡。
解散群組只是刪掉群組節點 —— **不需要搬動任何筆畫資料**，
維持 append-only 不變式。

### 4. 對齊與吸附是純幾何，與資料模型分離
對齊算出的是**新的變換矩陣**，不是新的座標。因此對齊也不破壞原始取樣點，
而且可以被復原。

## 格式影響
`.padnote` 新增五個 `DocOp`：
`AddObject` / `RemoveObject` / `SetObjectTransform` / `Group` / `Ungroup`。

`spec_version` 維持 1：舊讀取器忽略未知的 op 類型會**靜默丟失群組資訊**，
因此 `min_reader_version` 在首次寫入物件 op 時提升為 2。

## 後果
- 渲染端必須套用變換 —— 多一次矩陣乘法，成本可忽略
- 命中測試要先把座標**反向變換**回物件空間
- 群組不改動筆畫資料，因此群組／解散是 O(1) 且完全可逆
