# ADR-0008：檔案互通策略

- 狀態：**已接受**（2026-09-12）
- 決策：D-09
- 相關：`docs/requirements-review.md` §6

## 背景
原始需求是「與市調的 10 款競品格式完全相容、彼此互通」。
經查證**無法達成**：

- 多數競品格式**專有且未公開**（Goodnotes、Notability、Samsung Notes、
  Noteshelf、Nebo）；Notion 與 Granola **根本沒有本機檔案格式**
- 「互通」是雙向的 —— 即使我們完美解析對方的檔案，
  **對方也不會讀 `.padnote`**
- 逆向工程專有格式多半違反對方服務條款

## 決策
改為**三層互通策略**：

### 第一層：PDF 作為通用交換格式 ⭐
**10 款競品全部都能讀寫 PDF 標註。** 這是唯一真正通用的途徑。
- 匯出：帶標準 annotation 的 PDF（他家軟體可讀、可繼續標註）
- 匯入：PDF + 既有標註層

### 第二層：Markdown 與 JSON 雙向
- Markdown：Obsidian 完全相容；Notion、OneNote 也支援 MD 匯入匯出
- JSON：`.padnote` 的結構以 JSON schema 公開

### 第三層：盡力而為的單向匯入
針對少數格式提供「盡力而為」的匯入，**明確不保證完整性、
不保證未來版本相容**。實作前必須逐一確認該 App 的服務條款。

### 第四層（單方面可做到的）：開放自己的格式
`format-spec.md` 已公開發佈。我們能單方面做到的「互通」是**讓別人讀我們**，
而不是反過來。

## 後果
- 產品文案不得宣稱「與 X 完全相容」—— 那是做不到的承諾
- PDF 的標註保真度成為關鍵指標（E3 升級為互通的核心）
- 匯入功能的 UI 必須明示「盡力而為」，避免使用者以為是完整遷移
