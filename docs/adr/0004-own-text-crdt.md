# ADR-0004：自行實作文字 CRDT

- 狀態：**已接受**（2026-09-12）
- 相關：`padnote-doc::text`、ADR-0002

## 背景
筆畫用 append-only + 墓碑就能收斂（ADR-0002），但文字不行 ——
「在第 5 個字後面插入」這種位置參照在併發編輯下會錯位。

## 決策
自行實作 **timestamped insertion tree**（RGA 家族）：每個字元記錄它插在誰的
後面（origin）而非「第幾個位置」，同 origin 下的併發插入以 `OpId` 遞減排序，
文字為前序走訪。刪除為墓碑。

不引入 yrs / Automerge。

## 理由
- 需求是**純文字**。粗體、標題、待辦這些屬性住在 `Block` 層級，不在字元流裡，
  用不到 yrs 的 rich-text 機制。
- 與既有的 oplog／Lamport 基礎設施一致，零額外相依。
- 收斂性可以用與 S3 相同的方式驗證，每條性質都有測試釘住。

## 後果
- 墓碑永不回收，長文件的節點數會持續成長（GC 策略列為待決 D-02）
- 若日後需要**字元層級**屬性（例如逐字高亮），應改用 yrs 而非擴充本實作
- 已驗證：三站 300 次併發編輯經加密同步後完全收斂，緩衝區歸零
