# 長期維護與營收模式（D-05）評估

> 「全免費、無後端 ⇒ 沒有營收，長期維護動力？」（`architecture.md` §商業可持續性）
> 撰於 2026-09-13 · 待拍板

---

## 先把實際的錢算出來

談營收模式之前，先看這個專案**每年真的要花多少錢**：

| 項目 | 費用 | 備註 |
|---|---|---|
| Apple Developer Program | **US$99／年** | 上架 iOS/iPadOS/macOS 的唯一必要支出 |
| Google Play 開發者帳號 | US$25 **一次性** | 已包含在 WP8 的規劃裡 |
| 伺服器 | **US$0** | 決策 D5：沒有後端 |
| 模型託管 | **US$0** | HF / GitHub Releases（決策 D4） |
| 隱私權政策與手冊的網址 | **US$0** | GitHub Pages |
| 網域（可選） | 約 US$10／年 | 不是必要的 |

**每年大約 US$99 —— 一百美金。**

這個數字改變了整個問題的性質。這不是一個「需要商業模式」的專案，
而是一個「需要一百美金」的專案。用訂閱制、後端、帳號系統去籌一百美金，
付出的複雜度與隱私代價完全不成比例 —— 而且會直接推翻 D5 與現在的隱私權政策
（「沒有帳號、沒有伺服器、不追蹤」正是這個產品的賣點之一）。

真正的成本是**時間**，而時間買不到。下面的選項要解的是「錢」，
不是「維護動力」—— 這件事必須分開看。

---

## 六個選項

### 選項 1｜不營收，當作個人作品

年支出 US$99 自己吸收。

- **優點**：零複雜度。不必寫收據驗證、不必處理退款、不必寫商業條款
- **缺點**：完全靠個人意願撐著
- **適合**：使用者規模小、維護量可控的階段。**現在就是這個階段**

### 選項 2｜捐贈（GitHub Sponsors / Ko-fi）

- **優點**：不需後端、不動產品、不影響任何使用者
- **實際收入**：開源專案的捐贈轉換率普遍低於 1%。以 US$99 的目標而言
  **綽綽有餘**；以「養活一個人」而言完全不夠
- **缺點**：幾乎沒有

### 選項 3｜App Store 付費下載（原始碼仍然開源）

Apache-2.0 允許任何人自行編譯，但多數使用者不會 —— 他們付的是
「不用自己編、自動更新、上架審查過」。這是成熟的開源模式（Delta Chat、
NewPipe 的變體、DuckDuckGo 的部分產品線都是類似邏輯）。

- **優點**：**不需要我們的伺服器**（App Store 自己處理收據），與 D5 不衝突
- **缺點**：付費牆會壓低安裝量，而這個 App 的價值有一部分來自「免費」的定位
- **注意**：Android 端上架付費 App 時，Apache-2.0 的原始碼仍然要可取得

### 選項 4｜免費 + 一次性解鎖進階功能（App 內購）

例如：基本手寫與錄音免費；語音轉錄、匯出整本 PDF、素材庫解鎖一次性付費。

- **優點**：**同樣不需要後端** —— StoreKit 與 Play Billing 都在裝置端處理。
  免費使用者不受影響
- **缺點**：要決定「哪些功能算進階」，而那個決定會一直被重新質疑；
  而且開源意味著任何人都能自己編一個全解鎖版 —— 這不是漏洞，是這個授權
  的必然結果，接受它就好

### 選項 5｜付費模型／素材包

語音模型與素材庫作為一次性下載購買。

- **優點**：邊界清楚（買的是內容不是功能），不需後端
- **缺點**：模型來自第三方（決策 D-07 的授權稽核），賣它需要重新檢視授權；
  素材包則要持續產出內容才有人買

### 選項 6｜自建後端與訂閱制

- **直接推翻 D5**，並使整份隱私權政策失效
- 為了每年 US$99 的支出去建立一個要長期維運、要負資料外洩責任的系統，
  代價與收益完全不成比例
- **不建議**

---

## 建議

**選項 1 + 2：不營收，加上一個捐贈連結。**

理由：

1. **US$99／年**。捐贈連結解決這個數字綽綽有餘，而且不動產品、不影響任何
   使用者、不需要任何後端。
2. **「免費、無帳號、無伺服器」是這個產品的差異化來源**。市調結論是
   「沒有任何競品同時做到一流手寫 + 一流錄音轉錄 + 中文 AI + 資料主權 + 免費」——
   加上付費牆，就少掉最後一項。
3. **選項 3 與 4 隨時可以加，而且不需要改架構**（兩者都不需要後端）。
   反過來從付費改回免費卻會得罪已經付錢的人。所以**先不做，保留選項**。
4. **真正的風險不是錢，是時間**。那是任何營收模式都解不了的問題，
   要靠的是把維護成本壓低 —— 這件事專案一直在做（單一字串來源、
   共用核心邏輯、每個修正都有測試釘住），而且**比任何營收模式都有效**。

---

## 要拍板的事

1. 接受「不營收 + 捐贈連結」嗎？若是，要放哪一個平台（GitHub Sponsors 需要
   通過設定；Ko-fi 較簡單）
2. 若將來改變主意，優先走選項 4（免費 + 一次性解鎖）而不是選項 3（付費下載）——
   因為前者保住「免費可用」這個定位

---

## 不建議的做法（記下來免得以後重新討論）

- **廣告**：直接違背隱私權政策，而且手寫筆記 App 放廣告會毀掉使用體驗
- **賣使用者資料**：不用解釋
- **訂閱制**：為了 US$99 建立一個要長期維運的收費系統
- **把開源當成行銷話術、實際上關鍵功能閉源**：Apache-2.0 已經發佈了，
  收不回去；而且那會失去現在唯一真正的競爭優勢
