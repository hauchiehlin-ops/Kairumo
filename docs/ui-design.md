## 1. 設計原則

### 1.1 從市調直接推導出的三條
1. **不卡比好看重要。** 「大 PDF 卡頓閃退」是 Goodnotes 評論區最高頻負評。
   任何動畫或效果若會影響 J1（墨跡 ≤9ms）或 J2（500 頁 PDF ≤1.5s），一律砍掉。
2. **不要有「儲存」按鈕。** 所有變更立即落盤（S-23 已驗證）。
   放一個儲存按鈕等於在說「我們可能會弄丟你的東西」。
3. **設定不要藏太深。** Goodnotes 常見抱怨之一是設定層級過深。
   任何書寫中會用到的選項，**最多一層**就要碰得到。

### 1.2 Padnote 特有的
4. **錄音是一等公民，不是附加功能。** 這是與 Goodnotes 最大的差異，
   UI 必須讓人一眼看到「這頁有錄音」。
5. **模型未下載時仍要能用。** 引擎與權限中心（I1）要說清楚缺什麼、
   缺了會怎樣，而不是把功能藏起來或直接報錯。

## 2. 資訊架構

```text
筆記本庫 ──┬─▶ 編輯器 ──┬─▶ 工具列（浮動、可收合）
           │            ├─▶ 錄音條（有錄音時出現）
           │            └─▶ 轉錄側欄（可開合）
           ├─▶ 搜尋
           └─▶ 設定 ──▶ 引擎與權限中心
```

**只有三個頂層畫面。** 每多一層，使用者就多一次迷路的機會。

### 2.1 首頁採用：今日工作台

首頁採用「今日工作台」版面：進入 App 後優先顯示可立即接續的筆記、最近錄音、
轉錄狀態與全部筆記。這比傳統筆記本封面牆更能凸顯 Kairumo 的核心差異：
手寫、錄音、轉錄在同一條工作流裡，而不是分散在不同入口。

首頁區塊順序：

1. 頂部搜尋列：搜尋筆記、轉錄、手寫辨識內容
2. 主要動作：新增筆記、開始錄音
3. 繼續：最近開啟與最近編輯的筆記
4. 最近錄音：播放狀態、波形、轉錄狀態
5. 全部筆記：緊湊卡片或列表，可切換排序與顯示模式

首頁不放行銷型 hero、不放大型裝飾圖。第一屏必須是可用的工作區。

## 3. 編輯器版面

```text
┌──────────────────────────────────────────────┐
│ ‹ 返回   線性代數 第三週        🔍  ⋯        │ ← 標題列（捲動時淡出）
├──────────────────────────────────────────────┤
│                                              │
│                                              │
│              書寫區域                         │
│          （佔滿，無邊框裝飾）                  │
│                                              │
│                                              │
├──────────────────────────────────────────────┤
│  ✏️ 🖊️ 🖍️ ✐  │ ⌫ ⬚ │ T 🖼️ │ ↩︎ ↪︎      │ ← 工具列（浮動、可移動）
├──────────────────────────────────────────────┤
│ ▶ ━━━━●━━━━━━━━━━ 03:24 / 45:10   轉錄 ▸ │ ← 錄音條（有錄音時）
└──────────────────────────────────────────────┘
```

### 3.1 書寫區域佔絕大多數
標題列在捲動時淡出，工具列可收合成單一按鈕。
**寫字的時候應該只看得到紙和筆。**

### 3.2 工具列分組（需求 5）
```text
[ 筆類 ] │ [ 擦除／選取 ] │ [ 插入 ] │ [ 復原 ]
 ✏️🖊️🖍️✐    ⌫ ⬚           T 🖼️ 📎      ↩︎ ↪︎
```

- **點一下**選取工具；**再點一下**展開該工具的設定（顏色、粗細）
- 設定就地展開，**不跳新畫面**（對應原則 1.3）
- 工具列可拖到四邊任一側，位置記在使用者偏好
- 長按工具列把手 → 收合成單一浮動按鈕

### 3.3 錄音條
有錄音時才出現。上面的波形是**可點的時間軸** ——
點任一處跳到該時刻，對應的筆跡會閃一下（功能 C1 的視覺回饋）。

## 4. 向 GoodNotes 學什麼、避開什麼

| 面向 | GoodNotes 的作法 | Padnote |
|---|---|---|
| 筆記本隱喻 | 書架、封面、翻頁 | ✅ 學。情感連結是它的護城河 |
| 放大書寫框 | 底部固定的放大框 | ✅ 學（A6）。重度手寫者的留存第一功能 |
| 紙張模板 | 豐富且可自訂 | ✅ 學（E5/E6） |
| 工具列 | 頂部固定 | 🔄 改為**可移動浮動** —— 左撇子與橫向書寫時頂部會擋手 |
| 設定深度 | 多層巢狀 | ❌ 避開。書寫中用得到的最多一層 |
| 訂閱牆 | 免費僅 3 本筆記本 | ❌ 避開。完全免費，無任何功能牆 |
| 錄音 | **沒有** | ➕ 我們的核心差異 |
| 中文 AI | **不支援** | ➕ 我們的核心差異 |

## 5. 「能不能用」要說清楚（引擎與權限中心）

`core::setup` 已實作狀態機（`FeatureStatus`）。UI 直接畫它：

```text
┌─ 功能狀態 ──────────────────────────────┐
│ ✅ 手寫與打字          可以使用          │
│ ✅ 錄音                可以使用          │
│ ⚠️ 即時轉錄            需要：語音模型     │
│                        [ 下載 213 MB ]   │
│ ⚠️ 中文標點            需要：標點模型     │
│                        [ 下載 269 MB ]   │
│ ✅ 手寫轉文字          可以使用          │
│ ⚠️ 同步                需要：同步資料夾   │
│                        [ 選擇資料夾 ]    │
└─────────────────────────────────────────┘
```

**三個要點**：
1. 缺什麼寫在功能旁邊，不要藏進錯誤訊息
2. 按鈕直接是解法（下載／選資料夾／開啟設定）
3. 權限被拒絕時按鈕變成「開啟系統設定」——
   再彈系統對話框會被忽略，使用者只會覺得按鈕壞了（已在 `setup.rs` 實作）

## 6. 轉錄側欄

```text
┌─ 轉錄 ─────────────────────┐
│ 03:12  下週三下午三點在研討室 │ ← 點文字跳播（C1/C4）
│ 03:18  開會，請大家準時參加。 │
│ 03:25  ⋯⋯（轉錄中）         │ ← 灰字 = 部分結果
│                            │
│ ⏳ 轉錄落後 4 秒            │ ← backlog_us 的視覺化
└────────────────────────────┘
```

- 部分結果用**灰字**，最終結果用黑字（`AsrSegment::is_final`）
- 「轉錄落後 N 秒」直接畫 `transcription_backlog_us()` ——
  不要假裝即時，使用者看得到延遲才不會以為當掉了
- VAD 未使用神經網路時顯示提示（`uses_neural_vad()` 為 false）

## 7. 深色模式、無障礙、i18n

| 項目 | 作法 |
|---|---|
| 深色模式 | **紙張本身不反轉** —— 反轉會讓手寫墨色變得詭異。改為降低白紙亮度、UI 轉深 |
| 動態字級 | 所有 UI 文字跟隨系統設定；書寫區不受影響 |
| VoiceOver | 工具列每個按鈕有標籤；筆畫區提供「本頁有 N 筆手寫、M 段文字」的摘要 |
| 語言 | 繁中（主）／簡中／英文。**介面語言與筆記內容語言分開設定** |
