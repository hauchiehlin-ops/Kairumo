# Android 對齊 Apple 的計劃方案（2026-09-17）

> 目標：Android 的**所有版面**（首頁、筆記頁、各種編輯視窗、工具列）與
> iOS / iPadOS / macOS 一致 —— 一樣的資訊架構、一樣的操作路徑、一樣的功能，
> 並且**之後不會再漂回去**。

---

## 0. 先把「一樣」定義清楚，否則做不完

「完全一樣」若指**逐像素相同**，在兩個平台上做不到，而且做到了也是錯的：
Android 有系統返回鍵、Material 的觸控回饋與對話框行為、不同的字體度量與
安全區；照抄 iOS 的樣子會讓 Android 使用者覺得這個 App 壞掉。

所以這份計劃把「一樣」定義成三層，**驗收也照這三層驗**：

| 層 | 定義 | 判準 |
|---|---|---|
| L1 資訊架構 | 每個畫面有哪些區塊、順序、每個區塊有哪些控制項、控制項的語系鍵與預設值 | **必須完全一致**，由核心規格表定義，兩端測試比對 |
| L2 行為 | 同一個操作走同樣的步數、同樣的結果、同樣的錯誤訊息 | **必須完全一致**，逐項腳本驗收 |
| L3 外觀 | 間距級距、圓角、字級階、顏色語意、圖示語意 | **同一份設計代幣**；平台原生控制項的呈現差異允許存在並列管 |

**允許的平台差異（白名單，其餘一律視為缺陷）**

| 差異 | 為什麼保留 |
|---|---|
| 返回手勢／返回鍵 | Android 的系統導覽，拿掉等於違反平台慣例 |
| 面板呈現：Apple `presentationDetents` sheet ↔ Android 可調高度對話框 | 系統能力不同（S-73：Apple 的 sheet 寬度由系統決定） |
| 低延遲墨跡實作：PencilKit ↔ `InkSurfaceView` | 平台專有，見跨平台落差盤點 |
| iCloud Drive ↔ SAF | Android 沒有對應物 |
| 裝置端 AI 後端：Apple 系統模型 ↔ Android 目前誠實回報「沒有」 | 見 S-20 備註，不是版面問題 |
| 連續頁面模式的細節 | A-07 已記為**刻意**的平台差異 |

> 這張白名單是活的：每次要新增一條，都要寫進這裡並說明理由。
> 沒寫進來的差異 = 缺陷。

## 4. 方案：先立閘門，再逐層補齊

> 順序刻意如此。先把 P-07 做掉，後面每一階段做完就**鎖住**，
> 否則做到第四階段時第一階段又漂了 —— 這個專案已經發生過兩次
> （見 TODO「Android 介面落後」與「第一次嘗試的紀錄（已被上面取代）」）。

### 階段 0：對齊的判準與閘門（P-07）　規模 M　**必須第一個做**

1. **畫面規格下沉核心**：新增 `crates/padnote-core/src/ffi_screens.rs`，
   用資料描述每個畫面：區塊 id、順序、每個區塊的控制項（id、語系鍵、型別、
   預設值、是否僅限某平台）。做法與既有的 `ffi_toolbar` / `ffi_paper` /
   `ffi_guides` / `ffi_layout` 完全一致 —— 這個專案已經證明這條路走得通。
2. **兩端各一個對照測試**：
   - Apple：XCTest 走 accessibility identifier 樹，比對核心規格。
   - Android：instrumented test 走 `onNodeWithTag`，比對同一份規格。
   缺一個控制項、順序不同、語系鍵不同 → **測試紅**。
3. **CI 閘門**：兩個測試都進 `.github/workflows/ci.yml`，與現有的
   `FFI bindings` / `Format compatibility` 同級。
4. **截圖回歸**（輔助，不當硬閘門）：兩端各產出主要畫面的截圖存進
   `docs/parity/`，PR 時人工看一眼。像素不比對 —— 那會每次字型更新都紅。

**驗收**：故意把 Android 首頁的一張卡片註解掉，CI 必須紅。

## 5. 為什麼這次不會再有衍生問題

前兩次「Android 介面落後」的修法都是**照著清單補畫面**，補完就沒有東西
守著它 —— 於是 Apple 端每加一個功能（S-83、S-87、S-90、S-91、S-93…），
差距就重新拉開一次。這次的差別只有一個：

**階段 0 的核心規格表 + 兩端對照測試 + CI 閘門。**

做完之後，「Apple 加了一個控制項但 Android 沒加」會在 **CI 上紅**，
而不是三個月後由使用者回報。這也是這個專案已經在用的模式 ——
版面（`ffi_guides`）、紙張（`ffi_paper`）、斷點（`ffi_layout`）、
工具列（`ffi_toolbar`）都已經下沉核心，只是**畫面本身還沒有**。

## 6. 風險

| 風險 | 對策 |
|---|---|
| 4a 的 oplog 新增 op 會讓舊版拒絕整份文件 | 與先前 33 個 op 同一個已知代價；同版本發布兩端，並在 format-spec 與相容性測試裡寫明 |
| 3a 改手勢容易弄壞手寫輸入 | 先寫 instrumented 手勢測試再改；實機複驗列 A 清單 |
| 規格表一開始定得太細會綁死版面 | 規格只描述**資訊架構**（L1），不描述像素；L3 走設計代幣 |
| 階段 1、2、4 都是 L，一次做完週期長 | 每個階段結束就上 CI 閘門，中途中斷也不會回退 |
